# Reflection 2: From Proto-Personas to Evidence-Based Personas

According to the IxDF Encyclopedia of Human-Computer Interaction, Personas are research-grounded user representations that guide design decisions. A key distinction exists between proto-personas — built from team assumptions — and validated personas derived from real user data (IxDF, 2023). Designing from unvalidated assumptions risks solving the wrong problems entirely.

In our first deliverable, we built proto-personas around retired UADY employees. As the project evolved, our team decided to redefine the target population to focus on active administrative and manual employees (ages 30–60) — a decision driven by project scope and stakeholder input. We then constructed new proto-personas for this group, but still based largely on assumptions: we anticipated medium-to-low digital literacy and predicted that the main pain point would be authentication issues such as forgotten passwords or usernames.

User research interviews, however, revealed that these assumptions were incorrect. Authentication was not a significant barrier for either group. The real and consistent frustration was navigation within the site — users struggled to locate the correct section for their documents because the portal structure followed internal administrative taxonomy rather than user task logic.

This finding directly shaped our prototype. We restructured navigation around user-familiar labels ("Mis CFDIs", "Fondo de Ahorro", "Otros Documentos"), added persistent section indicators so users always know where they are, and reduced the number of clicks required to reach a document. As the IxDF framework warns, proto-personas built on assumptions can be worse than no personas at all, because they generate false confidence. Had we skipped user research, we would have refined an authentication flow that users did not need, while leaving the actual navigation problem unresolved.
