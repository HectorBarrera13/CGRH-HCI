### Processing HCI
Lean UX shifts the focus from rigid documentation to a continuous by collaboration and rapid hypothesis testing instead of exhaustive testing, where the process is always starting with declare assumptions, create an MVP and validate the process by running those experiments, if it doesn't work, it's quickly abandoned without having spent too many resources.

Our team's process was not entirely lean, it's a fact that we may have sort of things focused on agile method like discard unnecessary processes but we prioritized initial software frontend and backend architecture before validating the interface with actual end users, an that is a problem right now that we saw in classes, where the login might not be the most suitable for a certain group of users.

Transitioning to a true Lean UX model would require shifting from independent roles to a workshop model like IBM, demanding developers and stakeholders to collaboratively sketch solutions from day one. In our case, Damian and I entered some time later, so the activities that we need to do to be considered lean is to holding meetings with the team and stakeholders to ensure alignment and a clearly defined problem.
